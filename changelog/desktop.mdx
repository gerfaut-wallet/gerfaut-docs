## 0.1.0

The first release: Gerfaut for Windows, macOS and Linux.

Gerfaut watches bitcoin wallets it cannot spend from. There is no key generation, no seed handling and no signing anywhere in the code, and no Send button in the interface.

### Added

- Add a wallet from an output descriptor, an extended public key or a single address. Paste it, scan a QR code with the camera, including the animated ones a signing device shows, or open a file.
- Gerfaut says what it recognized, which script type and which derivation it uses, and waits for you to confirm before it stores anything. It refuses anything that carries private material.
- Watch several wallets at once. Rename them, give them an icon, reorder the list.
- Balance, transaction history, transaction detail with its inputs and outputs, unspent outputs in a table of their own, and the next receive addresses.
- A wallet whose descriptor holds a Miniscript policy gets a page for it. The page shows every spending path, who can take it, and the countdown left on the ones that wait for a timelock.
- Export the history of a wallet as CSV.
- Broadcast a transaction someone else signed. Paste its hex, open the file a signing device wrote, or scan its QR code. Gerfaut shows what the transaction does before it sends anything. When a signature is still missing, the preview reads `Not fully signed` and the `Broadcast` button stays disabled.
- When no backend confirms a coin a PSBT spends, the preview says so in amber and marks the fee and the input total as what the PSBT claims. Check them on a backend you trust, or on the signing device, before you send.
- Mainnet, signet, testnet4 and regtest.
- Public Esplora servers by default, or your own node over Esplora or Electrum.
- Gerfaut shows you an Electrum server's self-signed certificate, with its fingerprint, subject and expiry, and trusts it only once you say so.
- A `.onion` backend goes through Tor. Gerfaut uses the Tor already running on the machine when there is one and starts its own otherwise, so a hidden service needs no second install. The built-in client is arti. The first connection takes up to a minute and a half while it bootstraps.
- Sync when Gerfaut opens and on demand. A rescan is a separate, explicit action.
- Live alerts, off until you turn them on in **Settings** > **Notifications**. Gerfaut then keeps one connection open to your backend and posts a system notification when a transaction reaches the mempool, incoming or outgoing, and again when it confirms. An Electrum server pushes the change within seconds. Gerfaut reads an Esplora backend once a minute, a few addresses at a time. A mempool instance pushes changes for the addresses it agrees to follow.
- The watch runs for as long as Gerfaut is open, minimised and locked included, and the pages update at the same moment. A notification names the wallet and the amount, in the display unit, and leaves the amount out while amounts are hidden. While Gerfaut is locked, a notification names no wallet and no amount. It only says that a transaction appeared, confirmed or is no longer coming, and whether it is outgoing. What the system already showed stays in its notification center after Gerfaut locks.
- Gerfaut announces a transaction once when it appears and once when it confirms, across restarts, whether the live watch or a sync you asked for saw it first. A fee bump on a payment already announced brings no new notification. Past three transactions in one wallet at once, one line counts the rest. Transaction notifications stop at 20 a minute, and the last one says more are coming.
- On Linux and Windows, when a pending payment confirms or is no longer coming while Gerfaut is still open, the new notification replaces the pending one, fee bumps included. On macOS, both stay side by side in the notification center.
- When a pending payment that Gerfaut announced leaves the mempool and nothing pays you instead, Gerfaut says so, such as `A pending payment of 0.00150000 BTC is no longer coming`. While amounts are hidden or Gerfaut is locked, the notification leaves the amount out. Gerfaut never folds it into the count of other transactions.
- **Settings** > **Notifications** shows where the watch stands, such as `Connected · Electrum · host` or `Polling every minute · host`. It also says what the open connection tells the server: what a sync already tells it, plus how long Gerfaut stays connected. With the `Automatic` backend, Gerfaut first tries an Electrum server of a public operator it already syncs with, because Electrum pushes changes. A `Send a test notification` button sits below, the one reliable way to know whether the system shows notifications.
- Gerfaut stores the wallet list encrypted. Its encryption key lives in the operating system's credential store: the Windows Credential Manager, the macOS Keychain or the Secret Service on Linux.
- Lock Gerfaut with a PIN or a password. While it is locked, the vault answers only what the lock screen needs. The window holds no descriptor and no balance until a secret goes through. Behind the lock, Gerfaut reads only the theme, whether you saw the welcome tour, the network and the kind of secret to ask for. Unlocking then lands on the same vault, on the same network.
- Export every wallet you watch into a backup sealed with a password of your own, as a file or as an animated QR code. The same backup restores on another machine or on the phone. It holds descriptors and addresses, never a private key or a seed. Where you pick the password, Gerfaut warns that someone who copies the file can try passwords offline.
- Restoring a backup that carries node settings shows what they would put in place: the server each network would use and the certificates Gerfaut would pin. Gerfaut refuses a backup that a newer Gerfaut wrote, and says so instead of reporting a wrong password.
- Fiat value beside the balance, in the currency you pick, from CoinGecko, Kraken or mempool.space. Amounts in BTC or in sats. Gerfaut asks no price source anything until you turn the fiat value on.
- Light and dark themes.
- A check for a newer version, from a button in **Settings** > **About** and on its own at most once a day while Gerfaut is unlocked. It asks GitHub for the latest release of the repository, with no identifier attached. When one of your backends is a `.onion` address, the request goes through Tor, the button included. When Tor is not available, Gerfaut sends nothing and **Settings** > **About** says so. Otherwise GitHub sees your IP address, as it would for any page you open on it. A switch in **Settings** > **About** turns the automatic check off.
- When a newer Gerfaut is out, a strip above the page says so, such as `Gerfaut 0.2.0 is available`. Its button opens **Settings** > **About**, where the download is, and `Later` closes the strip for that version. The strip takes no focus, covers nothing on the page and never appears on the lock screen. The download button always opens the repository's releases page, whatever address the answer carried.
- Opening Gerfaut while it already runs brings its window to the front instead of starting a second copy.
- When the vault cannot open at startup, the window says why and offers `Try again`. This covers a vault that another copy of Gerfaut holds, such as a second installation on the same data folder. Two copies can no longer open the same vault and save over each other's changes.
- The Broadcast preview warns in red when an input is signed with `SIGHASH_NONE` or `SIGHASH_SINGLE`. Such a signature leaves the outputs open. Whoever relays the transaction before it confirms can then send some or all of the money elsewhere. The confirmation dialog repeats the warning.
- A `This is my node` switch under the address of your own Electrum or Esplora server, in **Settings** > **Network**. With it on, Live follows up to 20,000 addresses instead of 2,000. Leave it off for a server you do not run, which would refuse most of them and learn every one. Saving the server address again keeps the switch as it was.
- When Live cannot follow every address, **Settings** > **Notifications** says how many addresses of how many wallets wait for the next sync, and how to lift the limit. Each wallet then shows `Live`, `Partly live` or `At next sync` in **Settings** > **Wallets** and on its Overview. On your own node, when the server itself refuses addresses, the note names the server setting to raise.
- `Always watch live first`, under **Settings** > **Wallets** > **Advanced**, picks the wallets Live follows before the others when it cannot follow every address.
- A screen that fails to render says so and offers `Reload`, instead of going blank.
- The first screen of an empty vault and the first page of the welcome tour show the full Gerfaut logo, the falcon over its name.
- Every release carries a `SHA256SUMS` manifest signed with minisign. The key and the commands are in [Verify a download](/getting-started/verify-your-download). The workflow that builds a release pins every action and packaging tool by hash. Every job runs with a read-only token, except the last one, which only drafts the release from the files the other jobs built.

### Changed

- Syncs use far less data. Gerfaut downloads only what a wallet does not have yet. A payment that Live notices costs a few kilobytes instead of the wallet's whole history. Gerfaut still reads a wallet in full when the vault opens and once a day.
- On the Receive page, `Next address` goes through at most 200 unused addresses past the next one. It skips any address that another app already received a payment on, and stops on the last one with a line that says why. A descriptor without a wildcard shows its single address, with nothing to skip to. The gap limit warning counts the unused addresses since the last used one, instead of how many times you selected `Next address`.
- When the outputs of a transaction pay more than its inputs bring, the Broadcast confirmation says there is no fee instead of calling it unknown.
- Export takes the date range as `YYYY-MM-DD` and reads whole days in UTC, the days of the file's `date_utc` column. When Gerfaut cannot read a day, it says so under the fields and exports nothing. The page subtitle adds that everything stays on this computer.
- In every choice group (unit, price source, theme, Tor, export direction), the chosen option is filled in the accent colour.
- The hints under `New transactions`, `Check for updates automatically` and `Currency` are shorter.
- Fiat values group their thousands with a space, like amounts in BTC and sats: `€74 074.07` instead of `€74,074.07`.
- With the fiat value on, a wallet on signet, testnet4 or regtest shows 0 in your currency, such as `€0.00`. Its coins used to be valued at the price of real bitcoin, but test coins are worth nothing.
- When every wallet is on the network shown, the backup export reads `All wallets (N)` instead of offering a choice of one.
- In Add a wallet, an input that fits a single network, such as a mainnet address, names that network instead of offering a choice of one.
- On the Policy page, a coin that Gerfaut cannot count down before the first sync reads `next known after the first sync` instead of `next in an unknown time`.
- With Live alerts on and the `Automatic` backend, once the watch has connected, syncs go first to its server, Blockstream's Electrum server on mainnet. Your syncs then show your addresses to one operator instead of two. A broadcast, a transaction preview and the older transactions of a watched address still go to mempool.space first. When `blockstream.info:700` fails, the watch moves to `electrum.blockstream.info:50002` before it falls back to mempool.space.
- frigate.2140.dev is no longer in the list of public servers. It is a Silent Payments server, of no use to a wallet that only watches. If you picked it, Gerfaut goes back to `Automatic`.

### Fixed

- The Overview no longer opens scrolled down after you leave a long settings page. Every page opens at its top.
- If you type a server address with its port in the host field, `Save backend` tells you to put the port in its own field. Gerfaut explains any other refused address under the button. It used to say `Saved. The server did not answer` while it had saved nothing.
- Restoring a backup that holds a private key, or a descriptor Gerfaut cannot watch, says so, and says that Gerfaut restored nothing.
- When the system's key store has no vault key while a vault is already on disk, Gerfaut no longer creates a new key that could never open it. The startup screen says the key is missing. `Try again` asks the store again.
- Restoring a backup whose wallets are all on another network left them out of sight until a restart, with the restored settings hidden too. Gerfaut now moves to the wallets' network and shows everything at once.
- With `Hide amounts` on, unlocking no longer shows the balances for an instant.
- When the price source stops answering, amounts show without their fiat value and the `Bitcoin price` card says the source did not answer, as **Settings** already did. Both used to keep the last price they had, however old.
- A setting the vault cannot save, on a full disk or while an antivirus holds the file, goes back to its saved value with the reason under it. This covers the network, a trusted certificate, the gap limit, a wallet's name or icon, and transaction notifications, whose switch then stays off.
- A link that nothing on the computer can open says so and shows the address to copy.
- A wallet page that cannot load says why, with `Try again`. A list of UTXOs that failed to load no longer reads as an empty one.
- In Add a wallet, `Back` keeps what you pasted. A wallet added on another network closes the dialog even when switching to that network fails, and the confirmation names the network.
- The `System` theme follows the system when it switches between light and dark.
- Scanning a long animated QR code no longer makes the window stutter.
- The network badge in the sidebar was hard to read. It now uses the colours of the dark sidebar.
- In **Settings** > **Wallets**, a narrow window no longer shrinks wallet names to nothing. A row puts its actions under the name when both do not fit.
- The UTXO and transaction lists no longer stretch to the bottom of the window when they are short.
- Placeholders in text fields were lighter than any other text. They now have the same contrast as secondary text.
- The arrow keys move through choice groups, `Enter` submits the app lock dialogs, and screen readers announce form errors.
- **Settings** > **Network** no longer says that Electrum servers cannot watch a single address.
- **Policy** > **Descriptor** shows and copies the whole wallet as one multipath descriptor, with `/<0;1>/*`. It used to show the receive branch alone, which watched the wallet without its change.
- In Add a wallet, the script type hints give the address prefixes of the wallet's network, such as `tb1q` on signet and testnet4, instead of the mainnet ones.
- In Add a wallet, a Taproot address no longer leaves a single character on a line of its own.
- On the Broadcast page, the input and output lists use the same icons as the diagram above them. An output to someone else points away, and change points back.
- The Tor mode you pick shows as selected at once, instead of about a second later. Turning on `New transactions` shows `Connecting…` while the live watch starts, instead of `Off`.
- With `New transactions` on and no wallet on the selected network, **Settings** > **Notifications** reads `Off until you add a wallet.` instead of `Off`.
- When the server itself refuses addresses, **Settings** > **Notifications** says so, instead of blaming Live's own limits.
- When a server takes only a certain number of your addresses, Live asks it again for all of them a day later, or an hour later when it took none. It used to wait until you changed the server settings or restarted Gerfaut, which could leave Live off for days. Two refusals still hold until you change the server settings or restart Gerfaut. One is a single address the server turns down, such as one with a history too long for it. The other is a cut from an ElectrumX server when Live uses too much of its resources, after which Live asks for fewer addresses.
- In Add a wallet, the first address belongs to the network you pick and changes when you pick another one. A key added on regtest shows its `bcrt1` address, not the `tb1` address of signet.
- In Add a wallet, a QR code with no receive or change path brings a notice. Gerfaut assumes the usual `0/*` and `1/*` and asks you to compare the first address with your signing device.
- The certificate list and the dialog that forgets a certificate say that syncs with that server fail until you select **Save backend** again and accept it. They used to say that Gerfaut would ask again at the next connection, which it does not. When the server does not answer at `Save backend`, the note says the same of a server that signs its own certificate.
- On an Esplora backend, Live checks every address in turn. It used to start over at the top of the list each time it reconnected, every half hour. It never reached the addresses further down, and a payment to one of them waited for the next sync.

### Security

- Gerfaut opens only the addresses it links to: the block explorer and its releases page. The window can no longer ask the system to open any other web address.
- When you pick a file to add a wallet or broadcast a transaction, Gerfaut refuses it unread if it is far too large to be one. The window no longer stalls on it.
- While Gerfaut is locked, it no longer opens a file dialog to save or open a backup.
- A QR code that announces billions of parts no longer closes Gerfaut. Gerfaut treats a sync that reports a transaction worth more than 21 million bitcoin as a failed server.
- Gerfaut refuses an Electrum host that still contains a port. A `.onion` name can then never reach the system resolver in the clear.
- The Broadcast preview checks each previous transaction it fetches against its transaction id, and adds up amounts with overflow checks. It flags a time lock only when an input's sequence enables it.
- Copying a descriptor keeps it out of the clipboard history and the cloud clipboard on Windows. On macOS and Linux, it stays out of the clipboard managers that honour the same flag. Gerfaut also clears it from the clipboard after a minute, unless you copied something else since. The confirmation says `for 1 minute`.
- The window can no longer call Tauri's window, webview, menu, tray and path commands, or emit events. It listens to the events Gerfaut sends, opens its short list of addresses and calls Gerfaut's own commands.
- On macOS, a second launch finds the first one through a socket in your own temporary folder, instead of the `/tmp` folder that every account on the Mac shares.
- With the fiat value on and a `.onion` backend on any network, the price goes through Tor too. Gerfaut asks for no price while Tor is out of reach. Before, the price source saw the computer's IP address every minute, at the same times as the Tor circuits. The Tor card in **Settings** > **Network** says so. When Tor is out of reach, the price lines read `Tor is not available, so no price was asked.`
