---
title: "Channels"
description: "Send Gerfaut Premium alerts to the ntfy app, Telegram, an e-mail address or a webhook you run, test each channel, and verify a webhook signature."
---

Add up to ten channels per Premium licence key in **Settings** > **Premium**, under `Channels`. Gerfaut sends a test through the first one you add.

<Tip>
An ntfy, Telegram or e-mail alert names the wallet and says what happened, never an address, an amount or a transaction id. A webhook carries the whole event.
</Tip>

## Add an ntfy channel

<Steps>
  <Step title="Select Add a channel, then ntfy">
    Gerfaut draws a random topic of 24 characters. Anyone who knows the topic can read the alerts, so keep it to yourself.
  </Step>
  <Step title="Select Open in ntfy">
    The ntfy app adds the subscription. Without the app on this device, select **Copy** and subscribe to the address in the ntfy app within one minute, before Gerfaut clears the clipboard. The line then reads `Linked`.
  </Step>
</Steps>

## Add a Telegram channel

<Steps>
  <Step title="Select Add a channel, then Telegram">
    Gerfaut shows a link code for `@GerfautAlertsBot`, good for one hour.
  </Step>
  <Step title="Select Open Telegram and press Start">
    Telegram sends the code for you. The line then reads `Linked` with the name of your chat. When Gerfaut shows a `/start` line instead, select **Copy** and send that line to the bot within one minute, before Gerfaut clears the clipboard.
  </Step>
</Steps>

## Add an e-mail channel

<Steps>
  <Step title="Select Add a channel, then E-mail">
    Enter the address, then send it:

    <Tabs>
      <Tab title="Desktop">Select **Add channel**.</Tab>
      <Tab title="Android">Select **Add e-mail**.</Tab>
    </Tabs>

    The address receives a six-digit code, and nothing else until you confirm it.
  </Step>
  <Step title="Enter the code and select Confirm">
    Enter the code in `Code` within an hour. The line then reads `Linked`. After five wrong codes, add the channel again for a new one.
  </Step>
</Steps>

E-mail alerts have [daily limits](/premium/limits#check-the-message-ceilings). Keep ntfy or Telegram for the alerts you need at once.

## Add a webhook channel

<Note>
The host of a webhook must be, and resolve to, a public address. The server refuses a private address, such as `192.168.1.10` on your home network or `100.64.0.1` on a tailnet.
</Note>

<Steps>
  <Step title="Select Add a channel, then Webhook">
    Enter the `https://` URL of your receiver and, for signed deliveries, a `Secret`.

    <Tabs>
      <Tab title="Desktop">Select **Add channel**.</Tab>
      <Tab title="Android">Select **Add webhook**.</Tab>
    </Tabs>
  </Step>
  <Step title="Receive the deliveries">
    The server posts one JSON body per event. The line reads `Linked`.

    ```json
    {
      "kind": "spend_detected",
      "wallet": "<the wallet id>",
      "wallet_name": "Cold storage",
      "at": 1789000000,
      "data": { "txid": "<the transaction id>", "value_sats": 31000, "height": null }
    }
    ```
  </Step>
</Steps>

<AccordionGroup>
  <Accordion title="Read the kind of an event">
    The `kind` names what happened:

    - **Wallet events:** `spend_detected`, `spend_confirmed`, `coins_gone`, `receive_detected`, `receive_confirmed`, `timelock_due`, `wallet_registered` or `wallet_refused`. A `timelock_due` event carries a `milestone` of `30d`, `7d`, `1d` or `open`. A `wallet_refused` event carries the server's sentence in `message`.
    - **Account events:** `device_connected`, `device_approved` or `key_changed`, with `null` in `wallet` and `wallet_name`, and the `device` and its `platform` in `data`.
  </Accordion>
  <Accordion title="Verify the signature of a delivery">
    With a secret, each delivery carries `X-Gerfaut-Timestamp`, in unix seconds, and `X-Gerfaut-Signature`, which is `sha256=` followed by the hex HMAC-SHA256 of `<timestamp>.<body>` under your secret:

    ```python
    import hmac, hashlib

    expected = hmac.new(secret, f"{timestamp}.{body}".encode(), hashlib.sha256).hexdigest()
    valid = hmac.compare_digest("sha256=" + expected, signature_header)
    ```
  </Accordion>
  <Accordion title="Receive alerts on a machine without a public name">
    Use ntfy instead of a webhook. Your machine then subscribes to a topic rather than waiting to be called.
  </Accordion>
</AccordionGroup>

## Test or remove a channel

Select the menu of a channel line, then **Send a test** or **Remove**. Removing a channel asks you to [confirm with your app lock](/premium/devices#confirm-sensitive-actions). Tests and confirmation e-mails share a limit of five an hour and 20 a day per licence key.

## Fix a channel that is not delivering

A channel line reads `Not delivering` when every delivery to the channel has failed for an hour or more. The note under the line starts with `Nothing has reached this channel since` and the date, then says what to do:

- **ntfy:** Select **Send a test** to try again, or remove the channel and add it again.
- **Telegram:** If you blocked `@GerfautAlertsBot` in Telegram, unblock it, then select **Send a test**. Otherwise, remove the channel and add it again.
- **E-mail:** Check that the address still receives mail, then select **Send a test**, or remove the channel and add it again.
- **Webhook:** Check that your receiver answers at its URL, then select **Send a test**, or remove the channel and add it again.

The note also gives the last error the Premium server met, such as `the channel could not be reached` or `the channel answered 403`. A test that goes through clears `Not delivering` at once.

The Premium server turns off a webhook that the internet cannot reach. Its line reads `Not delivering` too, with a note that says why. Remove the webhook, then add it again with a public address.
